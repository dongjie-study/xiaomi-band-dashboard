## 一、导航怎么来的

`workbench.html`（工作台；根 `index.html` 现为**入场展示页**，点击「进入工作台」跳到它）自身**不含模块数据**，运行时 `fetch('modules.json')` 后调三个渲染函数：

| 函数 | 作用 |
|------|------|
| `renderSidebar(config)` | 填 `#sidebarNav` |
| `renderModuleCards(config)` | 填首页卡片 `#moduleGrid` |
| `buildModuleRegistry(config)` | 建全局 `modules` 注册表 |

**加/改模块只需改 `modules.json`，不用动 HTML。**

例外：模块的「月份 → 日期」二级菜单。`buildMonthDates()` 原来只认销售页的 `window.__STATS__.dates`；现在按模块分流——`sales` 走原路，其它模块走 `MODULE_DATE_SOURCE`（`workbench.html:1311`，目前只有 `traffic: 'traffic_analysis/data/index.json'`），日期取该文件 `days[].date` 并倒序，点日期调 `openModuleDate(modId, baseUrl, date, el)` → `iframe.src = baseUrl + '#' + date`。所以：

- 给已有模块加日期菜单：`subModules` 里写 `{ "title": "十月", "monthKey": "2026-10" }`（带 `monthKey` 就走日期展开，不再需要 `url`）
- 给新模块加日期菜单：在 `MODULE_DATE_SOURCE` 里加一行 `模块id: '该模块的 data/index.json 路径'`（文件名必须叫 `data/index.json`，`baseUrl` 由它反推）
- 月份条目带 `data-month-module` / `data-month-key`，日期列表容器 id 为 `monthDates_<模块id>_<月份>`；多模块都有「十月」时靠这两个属性区分高亮

## 五、第三方 JS 库：一律走国内镜像（npmmirror）

**背景**：这些库以前全从境外 CDN（jsdelivr / unpkg / sheetjs.com）**同步阻塞**加载，而站点本身在国内访问也慢，实测单库要 **18–45 秒**才能下完，页面白屏干等。2026-09-24 已全站换到阿里 npmmirror，实测 **0.08–0.26 秒**（快 100–300 倍）。

### 硬性约定

**新增或修改页面时，第三方库一律用 `registry.npmmirror.com`，不要用 jsdelivr / unpkg / cdnjs。**

| 库 | 地址 | 备注 |
|---|---|---|
| echarts 5.5.0 | `https://registry.npmmirror.com/echarts/5.5.0/files/dist/echarts.min.js` | 12 个页面在用（含 `traffic_analysis/index.html`） |
| chart.js 4.4.0 | `https://registry.npmmirror.com/chart.js/4.4.0/files/dist/chart.umd.js` | ⚠️ 文件名是 **`chart.umd.js`**，npmmirror 上没有 `chart.umd.min.js` |
| exceljs 4.4.0 | `https://registry.npmmirror.com/exceljs/4.4.0/files/dist/exceljs.min.js` | |
| vue 3 | `https://registry.npmmirror.com/vue/3.5.43/files/dist/vue.global.prod.js` | 用 **prod** 版，596KB → 148KB |
| xlsx | `https://registry.npmmirror.com/xlsx/0.18.5/files/dist/xlsx.full.min.js` | ⚠️ SheetJS **0.20.x 没发布到 npm**，npmmirror 最高只有 0.18.5；用 `defer` 加载并保留 sheetjs.com 兜底 |

### 三个必须沿用的写法

1. **`defer`**：只在点击/拖拽处理器里用到的库（xlsx、exceljs）加 `defer`，不进关键渲染路径。页面初始化就要用的库（echarts / chart.js / vue）保持同步，但换了源之后只阻塞 0.1–0.2s。
2. **兜底一行**：echarts / chart.js / vue / exceljs 后面跟一行 `if(!window.X){document.write(...)}` 指回原境外地址。只在 npmmirror 挂掉时才触发。
   > 写法用 `'<scr'+'ipt ...'` 拼接，**不要写 `<\/script>`** —— 生成器脚本是 `f'''` 三引号，反斜杠会踩到转义坑。
3. **生成器同步改**：`tools/generate_*.py` 里的 CDN 地址要和产物 HTML 一起改，否则重跑会回退。

### 🚫 不要「把库下载进仓库本地化」

本仓库文件由 **Cloudflare Pages** 提供，它传大文件同样极慢（实测 1.56MB 的 `sales_analysis/history.json` 要 70 秒、直接超时）。
本地化只是把「慢」从 CDN 挪到站点自身，**更糟**。走 npmmirror 才是对的。

## 六、全站悬浮组件（数据小管家的小图标）

**每个页面右下角那颗小米橙小球**，点开弹出对话框直接问数据。2026-09-26 上线。

| 项 | 值 |
|---|---|
| 组件本体 | 根目录 **`assistant-widget.js`**（纯原生 JS，零依赖，**Shadow DOM 样式隔离**） |
| 注入方式 | 各页 `</body>` 前一行 `<script src="assistant-widget.js?v=N" defer></script>`（子目录自动 `../`） |
| 维护脚本 | `tools/inject_widget.py`（幂等：`--check` 预演 / 直接跑=注入更新 / `--remove` 移除） |
| 覆盖范围 | **27 个页面**；**排除** `数据小管家/index.html`（它本身就是聊天页） |
| 当前版本 | `?v=3`（组件内 `VERSION` 常量与注入脚本里的 `VERSION` 必须一致） |

### 三条必须知道的规则

1. **不占任何 CSS、不影响现有页面**
   组件用 Shadow DOM 自带样式，**不引用 `theme.css` / `common.css`，也无需在任何页面加样式**。
   宿主页面的通配样式（`*{}` 之类）同样影响不到它。所以「悬浮球样式丑了」→ 只改 `assistant-widget.js`，别去改页面 CSS。

2. ⚠️ **脚本生成的页面重跑后会丢掉悬浮球**
   生成器（见 §二表格）是**整份重写 HTML**，注入的那行会一起被冲掉。
   受影响：`月度总结/*`（4 页）、`耳机专报/耳机销量分析报告.html`、`节点总结/618复盘总结.html`、`output/*`。
   **跑完生成器后补一次**：
   ```bash
   python tools/inject_widget.py --check    # 先看哪几页掉了
   python tools/inject_widget.py            # 补回来
   ```
   > 不用改生成器脚本 —— 注入脚本是幂等的，补跑一次就够。

3. **改了组件要加 `VERSION`**
   `assistant-widget.js` 顶部的 `VERSION` 和 `tools/inject_widget.py` 里的 `VERSION` 一起 +1，再跑注入。
   否则同事浏览器拿的是旧缓存，表现为「你改了但线上没变化」。

### 它为什么不会「出现两个球」

组件开头有一句 **`if (window.self !== window.top) return;`** ——
`workbench.html` 是用 iframe 加载各模块页的，子页面里的组件会静默跳过，
只由最外层的壳渲染一个球。**这段判断不能删。**

### 新增页面后

```bash
python tools/inject_widget.py --check    # 新页面会显示 added
python tools/inject_widget.py            # 注入
```

忘了跑 = 新页面右下角没有球，其余功能不受影响。
