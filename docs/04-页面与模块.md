## 一、导航怎么来的

`workbench.html`（工作台；根 `index.html` 现为**入场展示页**，点击「进入工作台」跳到它）自身**不含模块数据**，运行时 `fetch('modules.json')` 后调三个渲染函数：

| 函数 | 作用 |
|------|------|
| `renderSidebar(config)` | 填 `#sidebarNav` |
| `renderModuleCards(config)` | 填首页卡片 `#moduleGrid` |
| `buildModuleRegistry(config)` | 建全局 `modules` 注册表 |

**加/改模块只需改 `modules.json`，不用动 HTML。**

## 五、第三方 JS 库：一律走国内镜像（npmmirror）

**背景**：这些库以前全从境外 CDN（jsdelivr / unpkg / sheetjs.com）**同步阻塞**加载，而站点本身在国内访问也慢，实测单库要 **18–45 秒**才能下完，页面白屏干等。2026-09-24 已全站换到阿里 npmmirror，实测 **0.08–0.26 秒**（快 100–300 倍）。

### 硬性约定

**新增或修改页面时，第三方库一律用 `registry.npmmirror.com`，不要用 jsdelivr / unpkg / cdnjs。**

| 库 | 地址 | 备注 |
|---|---|---|
| echarts 5.5.0 | `https://registry.npmmirror.com/echarts/5.5.0/files/dist/echarts.min.js` | 9 个页面在用 |
| chart.js 4.4.0 | `https://registry.npmmirror.com/chart.js/4.4.0/files/dist/chart.umd.js` | ⚠️ 文件名是 **`chart.umd.js`**，npmmirror 上没有 `chart.umd.min.js` |
| exceljs 4.4.0 | `https://registry.npmmirror.com/exceljs/4.4.0/files/dist/exceljs.min.js` | |
| vue 3 | `https://registry.npmmirror.com/vue/3.5.43/files/dist/vue.global.prod.js` | 用 **prod** 版，596KB → 148KB |
| xlsx | `https://registry.npmmirror.com/xlsx/0.18.5/files/dist/xlsx.full.min.js` | ⚠️ SheetJS **0.20.x 没发布到 npm**，npmmirror 最高只有 0.18.5；用 `defer` 加载并保留 sheetjs.com 兜底 |

### 三个必须沿用的写法

1. **`defer`**：只在点击/拖拽处理器里用到的库（xlsx、exceljs）加 `defer`，不进关键渲染路径。页面初始化就要用的库（echarts / chart.js / vue）保持同步，但换了源之后只阻塞 0.1–0.2s。
2. **兜底一行**：echarts / chart.js / vue / exceljs 后面跟一行 `if(!window.X){document.write(...)}` 指回原境外地址。只在 npmmirror 挂掉时才触发。
   > 写法用 `'<scr'+'ipt ...'` 拼接，**不要写 `<\/script>`** —— 生成器脚本是 `f'''` 三引号，反斜杠会踩到转义坑。
3. **生成器同步改**：`tools/generate_*.py` 里的 CDN 地址要和产物 HTML 一起改，否则重跑会回退。

### 🚫 不要「把库下载进仓库本地化」

本仓库文件由 **Cloudflare Pages** 提供，它传大文件同样极慢（实测 1.56MB 的 `sales_analysis/history.json` 要 70 秒、直接超时）。
本地化只是把「慢」从 CDN 挪到站点自身，**更糟**。走 npmmirror 才是对的。
