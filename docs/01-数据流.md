## 一、三条独立链路

```
                        ┌─────────────────────────────────────────────┐
   订单 Excel            │  A. 订单链路（销售分析）                     │
   （x.xx日订单.xlsx）───▶│  run_all.py sales <excel>                   │
                        │      └─▶ sales_analysis/daily_update.py     │
                        │            ├─▶ history.json          ⭐主库  │
                        │            ├─▶ b10pro_history.json          │
                        │            ├─▶ band11_history.json          │
                        │            ├─▶ stats_data.js  （首页概览）   │
                        │            ├─▶ hourly/<日期>.json （小时明细）│
                        │            └─▶ 3 张 PNG（dashboard 等）      │
                        │      └─▶ 复制以上产物到 output/              │
                        └─────────────────────────────────────────────┘
                                          │
                                          ▼  history.json（只读）
                        ┌─────────────────────────────────────────────┐
                        │  C. 总结链路（首销月专用，仅 9.7~10.7）      │
                        │  band11_review.py context → 人写稿 JSON     │
                        │  band11_review.py add     ─▶ daily_summary.json ⭐
                        │  generate_band11_target.py                  │
                        │      └─▶ 桌面《小米手环11首销月目标进度表.xlsx》│
                        └─────────────────────────────────────────────┘

   业绩 Excel            ┌─────────────────────────────────────────────┐
   （x.xx日业绩.xlsx）───▶│  B. 业绩链路（业务面板）                     │
                        │  解析 → 手工插入（或 archive/ 里那支已禁用的 │
                        │  但 WORKFLOW 明令不跑）                      │
                        │      └─▶ 主播业绩/业绩demo.html              │
                        │            └─ DAILY_RECORDS  ⭐主库          │
                        └─────────────────────────────────────────────┘
```

**A 和 B 完全不交汇**：A 不碰 `业绩demo.html`，B 不碰 `sales_analysis/`。
C 只**读** A 的产物，不改任何数据（除了自己的 `daily_summary.json`）。

## 二、谁是上游、谁是下游

| 文件 | 角色 | 被谁读 | 被谁写 |
|------|------|--------|--------|
| `history.json` | 销售累计主库 | `tools/generate_*_summary.py`（月报）、`band11_review.py`、`generate_band11_target.py`、`tools/migrate_reclassify.py`、`gen_watch_compare.py` | 只有 `sales_analysis/daily_update.py` |
| `daily_summary.json` | 总结主库 | `generate_band11_target.py` | 只有 `band11_review.py add` |
| 业绩demo.html `DAILY_RECORDS` | 业绩主库 | 页面自己 | 手工插入（脚本法已被禁用） |
| `直播间服务商汇总.md` | **运行时数据文件** | `直播间销量汇总.py:load_service_map()` | `tools/gen_room_docs.py` |
| `team_config.py` | 归属配置 | 7 个脚本 | 手工 |

> ⚠️ `直播间服务商汇总.md` 看着像文档，其实是**被代码解析的输入**，
> 有硬格式契约，见 [`06-踩坑与故障.md`](06-踩坑与故障.md#4-直播间服务商汇总md-是运行时输入不是文档)。

## 三、页面产物的两种命运

| 类型 | 改了会怎样 | 例子 |
|------|-----------|------|
| **脚本生成** | 下次重跑**覆盖**，必须改生成器 | `月度总结/*.html`、`耳机专报/*.html`、`节点总结/618复盘总结.html` |
| **手写** | 直接改，长期有效 | `index.html`（入场展示页）、`workbench.html`、`主播业绩/业绩demo.html`（除 `DAILY_RECORDS` 块）、`竞争方案/*` |
| **构建产物** | 不要手改，会被覆盖 | `output/`（`.gitignore` 已忽略） |

完整对照表见 [`04-页面与模块.md`](04-页面与模块.md)。
